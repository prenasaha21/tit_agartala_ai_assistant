# Exercise: Build a Student/Applicant Assistant for Tripura Institute of Technology (TIT), Agartala

<img src="https://titagartala.ac.in/wp-content/uploads/2023/05/cropped-logo-1.png" alt="TIT Agartala Logo" width="100"/>

### Overview

In this exercise, you will build a **student and applicant assistant** for **Tripura Institute of Technology (TIT), Agartala**, a real government engineering institute in Tripura, India. The assistant will guide prospective applicants and current students through admissions, academics, departments, and campus information, answering questions about institute policies and providing personalized responses based on the user's information. You will use **Streamlit** to build a graphical user interface and **LangChain** to integrate **Retrieval Augmented Generation (RAG)**. The assistant will augment its responses using a vector store filled with information extracted from a provided PDF of TIT's institute information (sourced from the official website, titagartala.ac.in).

The assistant will leverage two data sources:
1. **User-specific data**: Generated by a synthetic data generator that emulates a student/applicant database.
2. **Institute information**: Retrieved from the provided PDF, stored in a local vector database, and used to answer questions about admissions, departments, fees, placements, and facilities.

---

### Business Context: TIT Agartala Student & Applicant Support

**Tripura Institute of Technology (TIT)** is a government-run engineering institute under the Department of Higher Education, Govt. of Tripura, offering AICTE-approved Diploma, B.Tech, and M.Tech programs. Prospective applicants and current students regularly have questions about admissions (TITLEE), courses, fees, departments, placements, and campus facilities — and getting quick, accurate answers can be a real pain point, especially during admission season.

The assistant you will create is designed to help users by providing personalized answers to their questions about admissions, courses, fee structure, placements, and other key aspects of life at TIT. The assistant will personalize its responses based on the specific user interacting with it (e.g., prospective applicant vs. enrolled student, department of interest) and will also retrieve answers from a vector store of the institute's official information.

### Instructions

#### 1. Fork and Set Up the GitHub Repository

Fork the provided GitHub repository to your own GitHub account and clone it to your local machine. The repository contains boilerplate code, including a **Synthetic Data Generator** module that will simulate student/applicant data, such as personal details, program, and department, which will be used by the assistant to personalize interactions.

Once cloned, create and activate a virtual environment in your local project directory, and install the dependencies from `requirements.txt`:

```bash
pip install -r requirements.txt
```

Now you're ready to start building the application!

#### 2. Display User Data

When a user interacts with the chatbot, display their **details** in the sidebar using Streamlit's `st.sidebar` feature. This will provide context for debugging and testing. You can use `st.write` to display the JSON generated by the synthetic data module. The user data will include:

- **Name**
- **Student ID**
- **Status** (Prospective Applicant / Enrolled Student / Alumnus)
- **Program level** (Diploma / B.Tech / M.Tech)
- **Department**
- **Year of study**
- **Interests**

The synthetic data will be generated by the `generate_student_data()` function from the **`students` module**, which is provided in the repository. You simply need to **import the module and use the function** to generate this information.

#### 3. Ingest Institute Information into a Vector Store

Next, you will use a provided PDF document containing TIT's institute information (vision/mission, departments, admissions, fees, placements, facilities, and contacts — compiled from the official website). Your task is to **ingest this PDF into a vector store** using a tool like **Chroma**, **FAISS**, or **Pinecone**, which allows for efficient similarity searches. The vector store will serve as the knowledge base for answering user questions. You will:

- Split the document into chunks.
- Generate embeddings for each chunk.
- Store the embeddings in the vector store, which will later be queried to augment responses.

This PDF includes sections on:
- **Institute overview, vision & mission**
- **Departments and programs**
- **Admissions (TITLEE process, prospectus)**
- **Fees, scholarships, and academic calendar**
- **Training & Placement Cell**
- **Campus facilities and contacts**

#### 4. Build the Chatbot Interface

Your chatbot should take user queries and respond using a language model API (such as an OpenAI or Groq-hosted model). The assistant will augment its responses with two data sources:
1. **User-specific data** (e.g., name, status, program, department).
2. **Institute information** stored in the vector store.

The assistant will handle common queries, such as:
- **"How do I apply through TITLEE?"**
- **"What's the fee structure for the CSE B.Tech program?"**
- **"Who is the HOD of Electronics & Communication Engineering?"**
- **"What does the Training and Placement Cell do?"**

#### 5. Structure the Application Using LangChain

Use **LangChain** to manage the interaction pipeline. You should define a **prompt template** that includes placeholders for the user data and retrieved institute information. The assistant will use this prompt to generate personalized and information-grounded responses.

It's recommended (but not required) to organize your code using a class structure, with methods such as:
- `render()`: to render the Streamlit front end.
- `get_user_data()`: to fetch the synthetic user data.
- `get_response()`: to generate a response by augmenting the user data and retrieving relevant information from the vector store.
- `retrieve_context()`: to query the vector store with embeddings generated from the user's question.

#### 6. Implement Streaming Responses

Enable **streaming** in Streamlit to display the assistant's responses in real time as the language model generates them. This feature will enhance the user experience by providing immediate feedback during the conversation.

#### 7. Cache User Data

Use **Streamlit's session state** or **LangChain's caching mechanisms** to store user data for the duration of the session. This avoids re-fetching or re-generating the synthetic user data with each new query and ensures a consistent context for the entire conversation.

#### 8. Test Common Use Cases

Test the assistant with several scenarios. For example:
- **Scenario 1:** A prospective applicant asks about the TITLEE admission process and deadlines.
- **Scenario 2:** A current CSE student asks who their HOD is and how to reach the department.
- **Scenario 3:** A final-year student asks about the Training & Placement Cell and how to get involved.

Ensure that the chatbot provides clear and helpful responses, augmenting answers with both user data and retrieved institute information, and honestly flags anything (like exact current fees or deadlines) that should be double-checked on the official site since such details change frequently.

### Additional Hints

- **Prompt Design**: Design the prompt template so that the language model has access to all the relevant context (user data, retrieved institute info) for generating responses. For example:

  ```text
  "You are an assistant for Tripura Institute of Technology (TIT), Agartala. The user, {name}, is a {status} interested in the {department} department ({program_level}).
  Based on the question: '{user_query}', retrieve any relevant information from the institute's official information and generate a helpful response."
  ```

- **Querying the Vector Store**: When a user asks a question, convert the query into embeddings and retrieve relevant chunks from the vector store. These chunks will provide context for the language model to generate an appropriate response.

- **Session State**: Use **Streamlit's session state** to maintain the user data and query history across multiple interactions.

- **User Interface**: Customize the UI to make it student/applicant-friendly, including buttons, text input areas, and a sidebar displaying the user's details.
